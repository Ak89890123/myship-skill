# 賣貨便功能盤點

2026-09-08，使用已登入 Chrome 的專用分頁查閱。初次盤點唯讀；後續經授權建立隱藏下架測試賣場及單雙規格商品，圖片與價格已讀回。未修改既有正式賣場。以下為已觀察功能，不代表 CLI 已全部完成。

## 一般賣場設定

來源：[新增表單](https://myship.7-11.com.tw/general/maintain)、[賣場清單](https://myship.7-11.com.tw/myship/list1)。

| 區塊 | 欄位與限制 |
|---|---|
| 基本資料 | 賣場名稱 50 字元、描述 3000 字元；描述使用富文字編輯器 |
| 賣場圖片 | 最多 3 張，每張 6 MB，建議 1440 × 400 |
| 狀態 | 正常／下架；公開／隱藏 |
| 期間 | 永久／指定起迄日 |
| 溫層 | 常溫／冷藏（僅宅配）／冷凍；既有賣場此欄停用 |
| 買家限制 | 不限／需有成交紀錄 |
| 訂單保留 | 60 天／90 天（僅取貨付款）；既有賣場此欄停用 |
| 買家回饋欄位 | 最多 5 則，單則 100 字元 |
| SEO | 關鍵字 100 字元，逗號分隔，建議不超過 20 組；網站描述 160 字元 |
| 物流 | 7-ELEVEN 店取／黑貓店到宅；固定運費、最多 3 組滿額運費、90 字元說明 |
| 付款 | 取貨付款（限店取）、icash Pay、藍新信用卡；依帳號開通狀態可能停用 |
| 儲存 | 預覽、儲存後接續新增商品 |

運費上限與活動會變動，CLI 應讀取目前表單。查閱當日常溫店取欄位上限 38 元、店到宅欄位上限 200 元；亦有訂單最低金額與 20,000 元含運費上限提示。

## 商品與規格

| 區塊 | 欄位與限制 |
|---|---|
| 商品資料 | 名稱 60 字元、必填描述 2000 字元 |
| 商品圖片 | 最多 7 張，每張 6 MB，建議 800 × 800；JPEG、PNG、GIF、BMP |
| 單規格 | 可新增其他規格；每列名稱、庫存、價格、優惠價與規格照片 |
| 雙規格 | 兩個規格名稱及選項，產生交叉組合；每組庫存、價格、優惠價；可全部套用 |
| 規格圖片 | 單規格依每個規格；雙規格依第一層選項，而非每個交叉組合 |
| 規格限制 | 名稱／選項 25 字元；DOM 驗證標示庫存 0–99999、價格／優惠價 0–20000 |
| 商品狀態 | 正常／下架；新品／二手 |
| 數量限制 | 單次下單上限、最低下單數量；0 表示不限 |
| 其他 | 複製商品、刪除商品、新增商品、查看商品順序、儲存並上架 |

「新增調整」浮動選單提供新增商品、查看商品順序。排序需要已儲存賣場且有足夠商品；目前只有一個商品，面板回覆「商品數量不足以更新排序」，未能驗證排序細節。

頁面提醒名稱與描述不要包含 `&()=;'"<>\,` 等特殊符號；CLI 應驗證並報錯，不自行刪字改文案。

## 清單與批次功能

1. 清單篩選：上架狀態、賣場類型；搜尋賣場名稱／商品名稱／商品規格；日期 1、2、6、12 個月或自訂；每頁 10、15、20、50 筆；依更新時間排序。
2. 每筆提供複製連結、修改賣場與新增商品、刪除、複製賣場；亦有多筆刪除。刪除、複製的提交未執行。
3. [批次上架](https://myship.7-11.com.tw/Store/Import)：限一般常溫／冷凍，最多 10 個賣場、每賣場 50 個商品；.xlsm／.xlsx，上限 2 MB。
4. [商品匯入紀錄](https://myship.7-11.com.tw/Product/Import)：指定賣場批次新增最多 100 個商品；.xlsm／.xlsx，上限 2 MB；紀錄顯示近 7 天。
5. Excel 匯入圖片僅接受 imgur、Google Drive、Dropbox；網頁標示支援 Windows Microsoft Excel。尚未下載／驗證範本結構。

## 其他類型及執行方式

另有[快速結帳](https://myship.7-11.com.tw/fast/add)與[便利自填單](https://myship.7-11.com.tw/easy/add)。前者用於已談妥交易，後者讓買家自行填金額與數量。目前只確認入口，先實作使用者需要圖片與多規格的一般賣場。

盤點使用 Codex 分頁控制；獨立 CLI 使用 Playwright 專用 Chrome 設定檔，由使用者另行登入 Facebook，不複製日常 Chrome cookies，不操作桌面滑鼠鍵盤。

Playwright 鎖定本機既有版本，使用官方 [persistent context](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context) 與[表單／檔案上傳 API](https://playwright.dev/docs/input)。

## CLI 實測補充（2026-09-08）

- `#UpdateGoodDateS_table` 是日期選擇器，不是賣場清單。清單為 `#AppContent .table > table`，列資料使用 `td[data-th]`；查詢按鈕觸發頁面導覽。
- 專用 Chrome 重啟後仍可登入並讀取賣場；不推論 FB 登入永不過期。快速登入只處理 FB 登入入口與既有連結的「以目前帳號繼續」。
- 實站已驗證賣場清單搜尋、一般賣場讀取、單規格讀取（主圖與規格圖分開），以及未儲存的新賣場單規格／新增商品雙規格填表。雙規格 2×2 的價格／庫存讀回一致。
- 自訂 radio 的 label 會攔截 input 點擊，填表改點 label 並確認 checked。
- 雙規格選項須觸發 blur 才更新交叉列。新商品索引不保證從 1 遞增（曾為 0），必須從 DOM 取得。
- 前一商品資訊未完整時，新增商品提示「需完成填寫前一個商品資訊後方可新增新商品!」。後續已驗證圖片與下架儲存，未測試正式發布。
- 賣場橫幅會開 Slim 裁切視窗，商品圖可能直接完成；依 data-state 判定，不能僅靠裁切視窗 visibility。儲存端點分別為 `/CPF2101/MaintainCgdm`、`/CPF2101/MaintainCgdds`，回應後仍須讀回確認。防詐確認按鈕須限定 `#popModal`，避免其他隱藏的同名按鈕。
